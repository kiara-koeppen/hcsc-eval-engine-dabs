Pull the data and set the study's time windows.

The engine reads the trusted, governed data, then sets the before and after periods the study needs. Some studies compare one period before and after; others track several periods over time.

  • Every setting for a study lives in one setup table, so you change a study by editing a setting, not writing code.
  • It handles both one-time before-and-after studies and studies that track several periods over time.
  • It runs one study or many, and each new study is just one more row in that setup table.
◼ hard stop if the data fails its quality check
Why it matters
Every study starts from the same governed, trusted data. Change a study by editing one setup table, not code.

Build the measures each study will use.

The outcome measures are built to each study's needs. Cost outcomes are supported today, and the same approach extends to other measures like comorbidity.

  • Some studies measure spend across several periods; others use a single before-and-after window.
  • The factors that make members comparable (age, risk score, comorbidities, prior use) are built once and reused.
  • Every step logs a pass / fail row with a plain-language note.
◼ hard stop if the measures fail their quality check
Why it matters
The same measures, built the same way, every time.

Make the data trustworthy before any analysis touches it.

Gaps are handled, outliers treated, negative dollars set to zero, and categories standardized. Then the cleaned data is saved as the input to the comparison step.

  • Each check writes a pass / fail row, with the reason, to the run log.
  • A data-quality failure halts the run. Unreliable data never reaches the analysis, so no silently-wrong result reaches a leader.
◼ hard stop, the engine halts and nothing downstream runs
Why it matters
Bad data is caught early, before it can skew a result.

Build a fair comparison group, the heart of a credible evaluation.

For each enrolled member, the engine finds statistically comparable non-enrolled members, so the comparison is truly like-for-like. It uses automated model selection to make that match rigorous, not hand-tuned.

  • The comparison is built the same way across studies, so results line up study to study.
  • If the two groups aren't similar enough to compare fairly, that's a quality-gate failure and the study stops.
◼ hard stop if the groups aren't comparable enough
Why it matters
A defensible, like-for-like comparison.

Measure the real impact, and let the engine correct itself.

The engine calculates how much of a difference the program actually made versus the comparison group, and checks that its method fits the data. This step doesn't hard-stop; it self-corrects.

  • If a statistical check on the method fails, the engine automatically switches to a more suitable method, with no one having to step in.
  • It records which method it used and why, so the result is defensible.
◆ self-correcting, the engine adapts and keeps going
Why it matters
The impact number holds up to scrutiny.

Land a standardized scorecard the business can read.

Results write to a governed table in a consistent scorecard format - overall and by subgroup - then surface to the dashboards and release notes leaders open. The output is a decision, not a 40-page deck.

  • Release notes translate every metric into plain language, so a non-technical leader can act on it.
  • Same format for every study - comparable across the whole portfolio, and reproducible under one run ID.

The payoff isn't only speed. AEE shows what happens when you pair the right AI levers with your experts on the calls that matter, build governance in from day one, and let the engine grow with every study it runs.

AI levers · human judgment
Built with AI, decided by your experts

We used AI assistance (Genie) and automated deployment (Databricks Asset Bundles) to design, orchestrate, and refine the engine and its front end in a fraction of the usual build time. The decisions that matter stayed with people: which model fits a study, and who counts as a comparable member, remain the call of your analysts and clinical experts.

Continuous improvement
It compounds as it runs

Every study and every new model that runs through AEE widens what it can do next. Adding a study or a method is a setting change, not a rebuild, so the engine keeps extending to new programs and new questions without starting over. Phase 2 brings this discipline to the pipeline itself, so improvements ship safely and repeatedly.

Governance · transparency
Every decision on the record

Governance is built in, not bolted on. Each study produces release notes that capture the key decisions and the reasoning behind them, so any result stays explainable and defensible long after the run, for a regulator, an auditor, or the next analyst.
